# Выполнение задачи этапа reqpipe (Claude Code)

## Команда reqpipe

В этой установке пакет вызывается так: `{{REQPIPE}}`.
Если в терминале нет команды `reqpipe` (пакет стоит в отдельном виртуальном окружении), везде ниже вместо
`reqpipe` пиши эту команду целиком; в PowerShell — через оператор вызова: `& {{REQPIPE}} next --json`.
Команды, которые печатает `reqpipe next` (поля `submit`, `approve`, `reject`), уже содержат правильный вызов.

Файл задачи — это карточка эталонной схемы плюс пакет контекста. Разделы:
«Назначение», «Как работать», «Ключевая инструкция», «Критерий готовности», «Входные данные (по
контрактам)», иногда «Результаты детерминированных проверок», «Доработка», «Ошибки формата», и в конце —
JSON-схема ответа.

## Порядок работы

1. Прочитай задачу целиком. Входные данные — единственный источник фактов о проекте.
   Если менеджер контекста что-то сократил, полный артефакт лежит в `artifacts/<источник>.json`.
2. Выполни «Как работать» и «Ключевую инструкцию». Роль из задачи — твоя роль.
3. Если есть раздел **«Доработка»** — исправь ровно перечисленные замечания. ID не перенумеровывай:
   правь существующие элементы, добавляй новые со следующими номерами.
4. Если есть **«Результаты детерминированных проверок»** — они уже нашли проблемы; учти их.
5. Перед ответом сверь результат с «Критерием готовности».

## Качество по видам этапов

- **Исследование (2.x, бенчмарк)**: WebSearch/WebFetch; у каждого факта `sources` с url, title, quote,
  accessed (ГГГГ-ММ-ДД). Нет подтверждения — это гипотеза, а не факт.
- **Требования (4.3)**: одно требование — одно поведение; шаблоны EARS («Когда <событие>, система должна
  <реакция>»); без «быстро», «удобно», «и т. д.», «при необходимости»; в `source_ids` — истории (US-…),
  обязательства (OBL-…), боли (PAIN-…).
- **Критерии приёмки и тесты (4.4–4.5)**: минимум позитивный и негативный сценарий на требование; один
  сценарий — один тест; локаторы через Page Object.
- **Фильтры (G0–G6)**: `verdict` = `fail`, только если есть замечания `critical`/`major`; каждое замечание —
  с `refs` (ID) и `target` (кому исправлять, из петель фильтра).

## Формат ответа

- Один JSON-объект строго по схеме: точные имена полей, все обязательные поля, правильные типы.
- Ссылайся только на ID, которые есть во входных данных или которые ты создаёшь сейчас.
- Валидный JSON: двойные кавычки, без комментариев и хвостовых запятых, кавычки внутри строк экранированы.
- В неинтерактивном запуске (`claude -p`) верни только JSON. Когда конвейер ведёшь ты — запиши его в
  `result_file` и выполни `reqpipe submit`.
