# Как вести конвейер reqpipe (OpenCode)

## Команда reqpipe

В этой установке пакет вызывается так: `{{REQPIPE}}`.
Если в терминале нет команды `reqpipe` (пакет стоит в отдельном виртуальном окружении), везде ниже вместо
`reqpipe` пиши эту команду целиком; в PowerShell — через оператор вызова: `& {{REQPIPE}} next --json`.
Команды, которые печатает `reqpipe next` (поля `submit`, `approve`, `reject`), уже содержат правильный вызов.

Пакет `reqpipe` — «мозг» конвейера: он хранит состояние, проверяет контракты между этапами, запускает
фильтры качества и петли доработки. Ты — исполнитель этапов и проводник для пользователя.
Команды `reqpipe …` запускай инструментом `bash`.

## Жёсткие правила

- Эталонная схема `requirements-pipeline.html` — **не изменять**.
- Не редактируй вручную `state.json`, `artifacts/`, `decisions.jsonl` в рабочей области. Пиши только
  в файл результата, который назвал `reqpipe next` (`results/<этап>.json`).
- Один этап за раз. Контекст этапа уже собран менеджером контекста в файле задачи — не подтягивай лишнее.
- Ничего не выдумывай: нет данных — так и пиши; результаты теста с людьми никогда не сочиняй.

## Старт

1. Если в проекте нет `.reqpipe/state.json`: возьми идею у пользователя (спроси, если её нет), сохрани в
   `idea.md` (инструмент `write`) и выполни `reqpipe init --idea idea.md`.
   - Если пользователь хочет «без участия человека» — добавь `--autonomous` (решения примет агент-арбитр).
2. При сомнениях в окружении: `reqpipe doctor`.

## Цикл

Повторяй `reqpipe next --json` и действуй по полю `action`:

- **task** — выполни этап по скиллу `reqpipe-stage`:
  1. Прочитай `task_file` целиком (`read`).
  2. Сделай работу. Если в `capabilities` есть `web` — используй веб-поиск и `webfetch`; у каждого факта
     источник с url, цитатой и датой.
  3. Запиши JSON строго по схеме в `result_file` (`write`).
  4. Выполни команду из поля `submit`. Код выхода 2 — ответ не прошёл контракт: исправь перечисленные
     ошибки и отправь снова.
  - Большой исследовательский этап можно поручить субагенту (инструмент `task`, агент general): передай
    путь к `task_file` и попроси вернуть только JSON; запись и `submit` делай сам.
  - **Этап 1.1 (интервью) в режиме с человеком** — это настоящий диалог: задавай пользователю вопросы по
    одному и дожидайся ответа, пока не закроешь проблему, аудиторию, контекст и критерии успеха; ответы —
    в `qa_log`, догадки — в `assumptions`. В автономном режиме (`autonomous` в задаче) не спрашивай:
    выбирай вероятные ответы и помечай их как допущения.
- **approval** — контрольная точка. Покажи пользователю `question`, `summary` и путь `artifact_file`,
  задай вопрос «Утвердить или вернуть на доработку?» и **дождись ответа**. Затем выполни `approve` или
  `reject --comment "<что исправить>"` со словами пользователя.
- **external** — тест с реальными пользователями (5.5). Покажи прототип (`prototype`) и план (`plan_file`),
  попроси пользователя провести сессии и прислать итоги. Собери из его слов JSON по `results_schema` и
  выполни `submit-external`. Если пользователь явно решил пропустить тест — `waive --reason "…"`
  (это попадёт в спецификацию как отметка).
- **looped / done** — сообщи одной строкой и продолжай цикл.
- **complete** — покажи пути к `SRS.md`, `requirements.json`, отметки (`flags`) и стоимость.
- **failed / stopped / blocked** — покажи `reqpipe status`, объясни причину, предложи
  `reqpipe rerun <этап> --comment "…"`.

После каждого этапа — одна короткая строка прогресса: номер, название, итог.

## Полезные команды

`reqpipe status` · `reqpipe spec` (домены, контракты, петли) · `reqpipe schema <этап>` ·
`reqpipe autonomy on|off` · `reqpipe check-reference` (сверка с эталонной схемой).
